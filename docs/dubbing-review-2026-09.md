# 配音節奏與通用性審查

基準：`api-cloud-webui` 的 `c3f862f5dc7d6f017a6754c6e23768658ece2f5a`。
範圍：翻譯上下文、Fish 請求與音檔、配音時間軸、FFmpeg 合成、快取、Gradio 操作流程。

## 已確認與修正

| 問題 | 影響 | 修正 |
| --- | --- | --- |
| 每句按字數估計把 Fish speed 從 1.0 改到最多 1.12 | 同一片的請求語速會跳動，超時又使後句延遲 | 每片固定語速，UI 預設 1.00，可調 0.85–1.15 |
| 保留 TTS 首尾長靜音，空白佔位音檔也推進時間軸 | 不必要的延遲累積 | 只保守清理首尾近靜音，保留句中停頓；無聲佔位不推進時間軸 |
| 語音檔存在即重用 | 改台詞、聲線、語速仍可能播到舊內容 | 每句以輸入指紋、檔案識別及 WAV 解碼驗證快取 |
| Fish 回應直接覆寫音檔 | 失敗／無效內容可能破壞可用音檔 | 暫存、驗證、原子替換；修復串流 WAV 標頭時按 RIFF chunk 解析 |
| 配音後審稿只記錄文字 | 重配音的時長改變後仍跳過審稿 | 指紋加入原時軸、實際時軸及音檔識別；時長量測與首尾靜音清理一致 |
| FFmpeg 使用原片時長限制已變速的成片 | 慢速輸出會截斷；加速與尾幀延伸計算不一致 | 先在原片時間補尾幀，再同步變速，輸出時長為 max(影音時長)/倍率 |
| 合成快取忽略輸出選項 | 改倍率、字幕、解析度等可能無效 | 比對完整選項與輸入／輸出檔案識別；字幕與無字幕都可正確快取 |
| FFmpeg 失敗時可把既有成片當作此次成功 | UI 顯示成功但實際是舊結果 | 只接受本次成功程序的完整暫存產物；驗證音訊與畫面兩條串流，失敗保留舊檔 |
| 音量僅在添加 BGM 的部分路徑套用 | 單獨調配音音量無效 | 所有合成路徑套用音量；額外 BGM 明確使用 filepath |
| 合併每句音訊都重新複製整條時間軸 | 長片越後面越耗時 | 累積片段後一次合併，移除反覆複製整片的成本 |
| 並行翻譯不帶鄰句上下文 | 回答、代名詞、用詞容易各句不一致 | 順序與並行翻譯都提供附近原文、講者與當前句標記 |
| 修仙專用字詞與句型被當作通用判定 | 換片可能誤改詞義或講者 | 停止自動替換河道／合道、停止按「你這個」句型改派講者、取消特定題材的硬拒絕條件 |
| 執行期提示讀取代理規則與歷史案例 | 不同作品可能沿用前一片設定 | 改讀可編輯通用風格文件及本片文字需求；模糊語意交給上下文審稿 |
| 全域設定可由不同 UI 工作同時更動 | 互相污染設定或寫入相同檔案 | UI 共用序列佇列；中止不用排隊，背景請求收尾後才釋放工作 |
| 備援翻譯套件在 UI 載入時連網 | 啟動延遲或卡住 | 需要備援翻譯時才匯入套件 |
| 繁體中文先被轉成 TTS 的「中文」別名 | 選錯譯文版本或找不到繁中譯文 | 配音流程保留翻譯語言，僅在供應商邊界做語言映射 |

## 使用方式

- 在「配音節奏」保持配音語速 1.00，英文譯文字數預算預設 2.2。
- 「本片翻譯風格／需求」是自由文字，依影片調整。預設偏自然口語與喜劇對話，不定義特定作品角色或詞彙。
- 「整片播放倍率」控制畫面與聲音一起變速，通常維持 1.00。
- 到「配音時間軸」查看逐句原片開始、配音開始、時長與延遲。延遲 ≥ 0.8 秒是檢查提示，不是自動砍掉台詞的條件。
- 譯文太長仍可能延遲。先修譯文；保持完整台詞，不為了追下一個時間點剪掉句尾。
- 改英文預算／風格僅影響之後的翻譯。要更新已存在譯文，勾「強制重翻」。舊譯文不會因升級自動全數改寫。

## 快取遷移與成本

舊版 WAV 沒有輸入指紋，無法證明是否對應目前的語速／文字／聲線。首次使用新版配音會重建這些舊音檔，可能產生供應商 API 費用。新版完成後，未變動且可驗證的音檔可以重用。配音參數存在每片 `dubbing_settings.json`，風格存在 `dubbing_style.json`；診斷寫入 `dubbing_timing.json` 與每句 `dub_timing`。

## 驗證

`python -m pip install -r requirements-dev.txt`

`python -m pytest -q tests`

在 Linux、Python 3.12 與實際 FFmpeg/ffprobe 下通過 **32 項測試**。包括實際 MP4 合成、0.5/1/1.5/2 倍速、保留完整尾音、字幕時間、首尾靜音、快取重用與失效、換聲線／語速、損壞 API 回應、RIFF 標頭、空白音檔、停止收尾、繁中語言版本，以及 Gradio 本機 HTTP 設定與回呼接線。API 相關案例使用可控回應，不使用帳號金鑰。

同一組合成素材與原版執行對照：

| 實驗 | 原版 | 新版 | 應有結果 |
| --- | ---: | ---: | ---: |
| 1 秒有效聲音＋首尾各 0.5 秒靜音；下一句應於 1.3 秒開始 | 下一句延遲 0.70 秒 | 延遲 0 秒 | 0 秒 |
| 2 秒畫面＋3 秒配音，以 0.5× 合成 | 成片 3 秒 | 成片 6 秒 | 6 秒 |

數值僅適用於上述可控素材，不是對任意動畫的效果保證。固定的是 TTS 的 speed 參數；供應商仍可依聲線、標點與表情產生不同自然節奏。

## 尚未驗證

- 真實中文沙雕動畫 → 雲端分離 → ASR → 翻譯／審稿 → Fish → 成片的完整品質。公開短片下載遇到來源端逾時／502，另一來源回傳 412；使用私有文件內金鑰的供應商測試也需要明確授權。未把這些步驟列為通過。
- 瀏覽器視覺與互動驗證：瀏覽器無法訪問執行環境本機網址。已驗證 Gradio 建構、HTTP `/config` 和關鍵回呼，但不等於完成畫面驗收。
- Windows / macOS 實機、長片壓力、真實聲線下的呼吸／尾韻，以及笑點和角色表演的主觀品質。
- 原專案仍有其他語言品質啟發式；本次移除高風險的跨題材自動判定，沒有把全部 NLP 規則一次重寫。

## 設計參考

影音變速與尾幀處理依 [FFmpeg filters 文件](https://ffmpeg.org/ffmpeg-filters.html) 的 `setpts`、`atempo`、`tpad` 與 `apad`；語速設定依 [Fish TTS API 文件](https://docs.fish.audio/api-reference/endpoint/openapi-v1/text-to-speech) 的 prosody 參數。
